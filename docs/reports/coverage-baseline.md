## 3. 门禁阈值映射

| 维度 | 基线值 | 门禁阈值 | 回归容差 | 退化触发阈值 | 目标值 |
|------|--------|---------|---------|-------------|--------|
| Lines | 24.89% | 28% | 2pp | < 22.89% | 30% |
| Branches | 75.83% | 75% | 2pp | < 73.83% | 75% |
| Functions | 49.79% | 50% | 2pp | < 47.79% | 52% |

**双层门禁机制**:
1. **绝对阈值** (`npm run coverage:gate`): 任一维度低于门禁阈值 → CI fail
2. **回归检测** (`scripts/architecture-guard.sh`): 任一维度低于基线值 − 2pp → CI fail

> 注：Lines 门禁阈值（28%）高于当前实测值（24.89%）——这意味着 R241 的覆盖率提升尚未稳定达到 28%，需在后续迭代中继续提升至 ≥30% 才能通过门禁。R243 的目标是**对齐门禁与实测**，杜绝"声称 35% 实测 24%"的虚报问题。

## 5. 更新规则

1. **收紧阈值**: 当覆盖率经实测确认稳定高于当前基线 ≥2pp 时，可向上修正门禁阈值，同时更新本文档基线快照
2. **修改容差**: 需经代码审查确认，容差不得 >5pp
3. **基线刷新**: 每次运行 `npm run test:coverage` 后，对比本文档中的基线值，如有显著变化（≥1pp）则更新快照
4. **谁有权修改**: 任何开发者可通过 PR 修改，但必须附带实测覆盖率输出作为证据
